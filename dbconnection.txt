DATABASE CONNECTION GUIDE

This project connects to Microsoft SQL Server (MSSQL) using PHP's sqlsrv
extension. Although the project runs through XAMPP, it uses SQL Server
for these database connections.

The local PHP CLI installation was checked: PHP 8.2.12 has both sqlsrv
and pdo_sqlsrv enabled. A live database connection was not tested.

HOW THIS PROJECT CONNECTS

1. Existing POS API
   existing-pos-api/index.php defines the connection settings and creates
   the $conn connection. Endpoints such as get_items.php include this file.
   existing-pos-api/online/index.php provides another connection setup
   for the online endpoints.

2. AI dashboard
   ai-chat/config.php loads settings from ai-chat/.env.
   ai-chat/db.php uses those settings to create the SQL Server connection.
   The dashboard calls QueryService, which calls DatabaseManager.

3. Current AI chat
   The chat sends queries to QUERY_API_URL.
   The optional ai-chat/api/query_execute.php connects to SQL Server using
   QUERY_DB_SERVER, QUERY_DB_NAME, QUERY_DB_USER, and QUERY_DB_PASS.
   This is separate from the dashboard's DB_* configuration.

For a normal PHP project, reuse the AI dashboard connection approach:

   PHP endpoint -> db.php -> config.php -> .env settings
                      |
                      v
                sqlsrv_connect()
                      |
                      v
                  SQL Server

STEP 1: GET YOUR DATABASE CONNECTION DETAILS

Ask your database administrator for these four settings:

   DB_SERVER: SQL Server address and port, or instance name.
              Example: 192.168.1.50,1433
   DB_NAME:   Database name. Example: MyNewDatabase
   DB_USER:   SQL Server login. Example: my_app_user
   DB_PASS:   Password for that login.

The database must already exist, and the login must have permission
to access it. Replace all examples with your actual connection details.

STEP 2: COPY THE CONNECTION FILES

If your new project is also PHP, copy these files into its root folder:

   ai-chat/config.php
   ai-chat/db.php

Create a file named .env beside them with this content:

   DB_SERVER=192.168.1.50,1433
   DB_NAME=MyNewDatabase
   DB_USER=my_app_user
   DB_PASS="your_actual_password"
   MOCK_DB_MODE=false

The copied config.php already loads the .env file. PHP does not load
.env files automatically. Existing nonempty environment variables take
precedence over values loaded by this project's .env loader.

Keep .env out of Git and block HTTP access to it.

STEP 3: TEST THE CONNECTION

Create test-db.php in your new project's root folder:

<?php
declare(strict_types=1);

require_once __DIR__ . '/db.php';

header('Content-Type: application/json; charset=utf-8');

try {
    $result = DatabaseManager::queryOne(
        'SELECT DB_NAME() AS database_name, 1 AS connection_ok'
    );

    echo json_encode([
        'success' => true,
        'result' => $result,
    ]);
} catch (Throwable $e) {
    error_log($e->getMessage());
    http_response_code(500);

    echo json_encode([
        'success' => false,
        'message' => 'Database connection failed. Check the PHP error log.',
    ]);
}

If your new project folder is C:\xampp\htdocs\my-new-project, start
Apache in XAMPP and open this address:

   http://localhost/my-new-project/test-db.php

A successful response should look like:

   {
     "success": true,
     "result": {
       "database_name": "MyNewDatabase",
       "connection_ok": 1
     }
   }

STEP 4: QUERY YOUR TABLES

Pass values separately using ? placeholders:

<?php
require_once __DIR__ . '/db.php';

$rows = DatabaseManager::query(
    'SELECT TOP 20 * FROM dbo.Products WHERE CategoryId = ?',
    [5]
);

Replace Products and CategoryId with your actual table and column names.
Do not concatenate user input into SQL.

HOW THE ACTUAL CONNECTION WORKS

Inside db.php, the connection is equivalent to:

$conn = sqlsrv_connect($server, [
    'Database' => $database,
    'UID' => $username,
    'PWD' => $password,
    'CharacterSet' => 'UTF-8',
    'TrustServerCertificate' => 'Yes',
]);

The $server, $database, $username, and $password values come from the
configuration. The resulting $conn is passed to sqlsrv_query() to
execute queries. DatabaseManager reuses its connection within the
current PHP request and returns query results as associative arrays.

DETAILS TO CONSIDER WHEN REUSING THE CODE

1. DatabaseManager::query() blocks commands such as INSERT, UPDATE,
   and DELETE. It is intended for reporting. If your new project needs
   to save data, implement separate parameterized write methods and
   give its database login only the permissions it needs.

2. The existing dashboard connection uses TrustServerCertificate=Yes,
   which skips certificate validation. For production, configure a
   trusted SQL Server certificate and enable certificate validation.

3. Configuring only DB_* values connects the dashboard and fixed
   reporting tools. The current conversational chat also requires
   QUERY_API_URL and QUERY_API_TOKEN. If using query_execute.php,
   configure QUERY_DB_* with a dedicated SELECT-only SQL Server login.
   The reference query API rejects the sa login.

IF THE CONNECTION FAILS

Check:
   - SQL Server address, instance, and port.
   - Network access from the PHP server to SQL Server.
   - Login username and password.
   - Database name and login permissions.
   - SQL Server certificate configuration.
   - The PHP error log for the actual connection error.

On another machine, install Microsoft's ODBC driver and the PHP SQL
Server extension matching that machine's PHP version, architecture,
and thread safety. Enable the extension in the PHP configuration used
by Apache, then restart Apache.

Official Microsoft setup instructions:
https://learn.microsoft.com/en-us/sql/connect/php/step-1-configure-development-environment-for-php-development?view=sql-server-ver17
